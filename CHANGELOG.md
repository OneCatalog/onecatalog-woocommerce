# История изменений — OneCatalog Import

Формат основан на [Keep a Changelog](https://keepachangelog.com/ru/1.0.0/),
нумерация версий — по [семантическому версионированию](https://semver.org/lang/ru/)
(`MAJOR.MINOR.PATCH`: ломающие изменения / новые фичи / багфиксы).

Версия задаётся в двух местах файла `onecatalog-import.php` — заголовок `Version:`
и константа `ONECATALOG_IMPORT_VERSION`; менять надо оба.

## [1.9.0] — 2026-06-21

### Добавлено — реакция на изменение состава фида + уведомления
- Новые справочники фида (регионы/поставщики/склады) **не применяются автоматически**:
  приоритеты хранятся по стабильным id (настройки не «слетают»), новые элементы
  показываются в списках приоритета с пометкой **«новое — не настроено»** и не влияют
  на цену, пока вебмастер их не настроит и не сохранит.
- **Баннер в админке** и **email администратору** при изменении состава фида (один раз
  на новый состав) и **при ошибке выгрузки** (троттлинг ≤ 1/час). Тумблер
  «Email-уведомления»; получатель — фильтр `onecatalog_b2b_notify_email`.
- Два снимка справочника: подтверждённый (`catalog_meta`) и последний из фида
  (`feed_meta`); разница = новые элементы.

## [1.8.6] — 2026-06-21

### Добавлено — журнал обновлений (B2B)
- Страница «OneCatalog → Журнал обновлений»: **история запусков** синка (начало,
  окончание, длительность, просканировано/всего, изменено, без изменений, в очередь
  импорта — последние 30) + прогресс текущего/последнего запуска + детали по страницам.
  Сводка каждого прогона пишется в `onecatalog_b2b_history`.

## [1.8.5] — 2026-06-21

### Добавлено — журнал импорта и ручной прогон очереди
- Страница «OneCatalog → Журнал импорта»: состояние очереди (в ожидании/в работе) и
  история последних результатов (статус создан/обновлён/пропущен/ошибка). Кнопка
  **«Выполнить очередь сейчас»** (`Queue::run_now()`) — прогон Action Scheduler, когда
  WP-Cron не срабатывает (тестовые сайты). Предупреждения про `DISABLE_WP_CRON`.

### Исправлено — ручной запуск B2B-синка без WP-Cron
- «Синхронизировать сейчас» теперь **браузерный степпер** (страница за страницей,
  синхронно) — не зависит от WP-Cron; раньше задача висела в `pending` без движения.
  При старте сбрасывается прогресс и отменяются зависшие задачи.
- Исправлен показ прогресса (использовался несуществующий `progress.done`).

## [1.8.4] — 2026-06-21

### Изменено — обновлённый формат B2B API
- Поддержан новый формат фида: справочник **`data.suppliers`** на верхнем уровне (как
  `regions`/`warehouses`), в оффере — скаляр **`supplier_id`** (вместо `supplier{id,name}`),
  `promo_price`/`purchasing_price` могут быть `null`. Поддержаны оба формата;
  `data.suppliers` добавлен в `$context` событий.

## [1.8.3] — 2026-06-20

### Добавлено — «отстойник» (staging) для unknown-товаров
- Режим unknown «Отстойник»: несопоставленные товары поставщиков складываются в таблицу
  `{prefix}onecatalog_b2b_staging` на **ручной отбор** — страница со вкладками
  Новые/Игнорированные/Импортированные и действиями «Импортировать выбранные» /
  «Игнорировать» / «Вернуть в Новые». Авто-создание всех остаётся отдельной опцией.

## [1.8.2] — 2026-06-20

### Добавлено — колонка «OneCatalog» в списке товаров
- Колонка с `public_id` (клик — **копирование в буфер**) и ссылкой **«Открыть»**
  (URL фильтруемый); если кода нет — инлайн-ввод с сохранением через REST
  `POST /onecatalog/v1/admin/set-public-id`.

## [1.8.1] — 2026-06-20

### Добавлено — авто-синхронизация цен/остатков по расписанию
- Настройка «Auto-sync»: выкл / час / 3 часа / 6 часов / день / неделя (рекуррентное
  действие Action Scheduler); для «каждый день» — выбор **времени суток** (часовой
  пояс сайта). Снятие расписания при деактивации.

## [1.8.0] — 2026-06-20

### Добавлено — синхронизация цен и остатков (B2B)
- **B2B-фид** `retailer-share-products` (отдельная авторизация: `url_key` в пути +
  `private_key` в query), пагинация, разведка регионов/складов/поставщиков.
- **`PriceStockSync`** по принципу **scan-and-diff**: фаза скана сравнивает сигнатуры
  цены/остатка в памяти (без загрузки `WC_Product`), фаза записи пишет порциями
  **только изменившиеся** товары. `known` → по `public_id`; цена — стратегия
  (приоритет поставщиков / минимальная / конкретный) × приоритет регионов (drag-drop),
  `promo>0 и <base` → акция; остаток — сумма по складам (дробные поддержаны).
- Цена/остаток — **живой фид**: перетирает значения синкаемых товаров (в отличие от
  импорта каталога, который цену не задаёт). Ненайденные known → Wiki-очередь / skip.
- **Поле кодов поставщиков** на товаре (для сопоставления unknown); **отдельные
  страницы** «Подключение B2B» и «Цены и остатки»; ручной запуск с прогрессом.
- **Точки расширения**: фильтры `onecatalog_b2b_*` (чтение/цена/остаток/сигнатура),
  события `onecatalog_b2b_before_update` / `onecatalog_pricestock_updated` (сырые офферы
  + справочники в `$context`) — для раскладки цен по регионам/остатков по складам.
  Справочник — `docs/B2B-HOOKS.md`, пример ACF — `docs/b2b-regional-pricing-example.php`.
- Полная локализация новых строк (`.pot`/`.po`/`.mo`).

## [Не выпущено] — бэклог

### Запланировано
- Одноразовый инструмент слияния дублей глобальных атрибутов: перепривязать товары
  на «правильный» атрибут и удалить лишний (для сайтов, где дубли уже накопились до 1.1.0).
- Опция «применять статус и к существующим товарам при переимпорте» (сейчас статус
  выставляется только новым).

### Известные нюансы
- Пункт подменю «Характеристики» появляется со следующей загрузки страницы после
  включения тумблера (меню строится на `admin_menu` до сохранения настроек) — на
  главной сразу даётся рабочая кнопка-ссылка.

## [1.7.0] — 2026-06-15

### Исправлено
- **Конверсия единиц веса/размеров.** OneCatalog отдаёт величины в наименьшей
  единице (вес — **граммы**, размеры — **миллиметры**), а раньше они писались в
  товар «как есть» — в единицах магазина (кг/см), из-за чего плитка 1200×600 мм
  становилась 1200×600 **см**, а вес в граммах — килограммами. Теперь значения
  конвертируются в настроенные единицы магазина (`woocommerce_weight_unit` /
  `woocommerce_dimension_unit`, зависят в т.ч. от страны).

### Добавлено
- Самодостаточный **универсальный конвертер единиц** `Units` (таблицы коэффициентов,
  нормализация локализованных подписей: «мм»/«г»/«inch»/…). Единица источника берётся
  из payload (`sizes.*_unit`), иначе мм/г. Фильтры `onecatalog_source_dimension_unit`
  и `onecatalog_source_weight_unit` для переопределения.

## [1.6.0] — 2026-06-15

### Добавлено
- **Коллекции — хранение в атрибуте.** К «Тип записи» и «Таксономия» добавлен
  способ **«Атрибут (характеристика)»**: коллекция кладётся термином в выбранный
  глобальный атрибут `pa_*` и прикрепляется к товару как видимый атрибут; поля
  коллекции (OneCatalog ID, 3D-ссылка, ссылка на сайт, обложка) сохраняются как
  term-meta (как в режиме таксономии). Опция `onecatalog_collection_attribute`.
  Теперь все три «справочные» сущности (коллекция, бренд, страна) поддерживают
  единый выбор «тип объекта (атрибут / таксономия / CPT) + цель».

## [1.5.1] — 2026-06-15

### Изменено
- **boolean-характеристики:** значения для true/false теперь выбираются **из
  выпадающего списка термов** привязанного атрибута (а не вводятся текстом); при
  смене атрибута списки переподтягиваются динамически.

### Исправлено / уточнено
- Пустое или отсутствующее значение `bool_option` из OneCatalog трактуется как
  **false** (берётся значение для false). Подтверждено для true/false/null/отсутствия.

## [1.5.0] — 2026-06-15

### Добавлено
- **Страна происхождения** — раньше попадала только текстом в краткое описание, теперь
  назначается структурно: настройка «Хранить страну как» — товарный **атрибут**
  (по умолчанию) или **таксономия**, с выбором цели. Класс `CountryImporter`,
  экшен `onecatalog_country_imported`.
- **boolean-характеристики.** Раньше bool-характеристики (Эксклюзив, Морозоустойчивость
  и т.п.) **не импортировались** вовсе — в payload у них `specification_option_name = null`,
  а значение в `bool_option`. На странице «Характеристики» для них теперь задаются
  значения терма для **true** и **false** (например, «Да»/«Нет»); они кладутся в
  привязанный атрибут.
- **Импорт тегов** — настройка вкл/выкл; теги кладутся в нативную таксономию
  `product_tag`, поиск по названию (существующий переиспользуется, иначе создаётся).
  Фильтр `onecatalog_import_tags`.
- `Api::specifications()` отдаёт тип характеристики (`text`/`boolean`/`numeric`).

### Примечание
- Остальные неиспользуемые поля payload (единица измерения, площадь упаковки, вид товара,
  alt/описание картинок, детали бренда, upsell/cross-sell и т.д.) намеренно оставлены
  на сторону интегратора — заполняйте их через экшен `onecatalog_product_imported`
  (в него передаётся полный payload товара).

## [1.4.0] — 2026-06-15

### Исправлено
- **Цена больше не выдумывается и не затирается.** В Wiki API цен нет — раньше цена
  ставилась синтетической формулой `600 + (id×173) mod 5000` и **перезаписывалась при
  каждом импорте**, затирая ручные правки. Теперь по умолчанию цена не задаётся: новым
  товарам — пусто (заполняет вебмастер), при переимпорте ручная цена сохраняется.

### Добавлено
- Фильтр `onecatalog_product_price` — подставить цену из своего источника
  (`null`/`''` — не задавать, поведение по умолчанию).

## [1.3.0] — 2026-06-15

### Добавлено
- **Дедупликация медиа.** Один и тот же файл/изображение, встречающийся у разных
  товаров (или как обложка и логотип бренда/коллекции), теперь скачивается один раз:
  по стабильному контент-ключу (`sha1(path#size)` из URL OneCatalog `media_files`)
  при загрузке ищется существующий attachment — найден переиспользуется, нет —
  скачивается и ключ записывается (мета `_onecatalog_file_key`). Встроено в `sideload()`,
  поэтому работает для обложек, галерей и логотипов брендов/коллекций. Фильтр
  `onecatalog_media_dedup` (по умолчанию вкл).

### Изменено
- При замене файла лучшим качеством общие (дедуплицированные) attachment больше не
  удаляются — чтобы не сломать другие товары, ссылающиеся на тот же файл.

## [1.2.0] — 2026-06-15

### Добавлено
- **Способ хранения бренда — выбор метода WooCommerce.** К существующим «Таксономия»
  и «Тип записи» добавлен **«Атрибут (характеристика)»** — старый способ WooCommerce,
  когда бренд хранится в товарном атрибуте `pa_*`: выбирается существующий глобальный
  атрибут, бренд кладётся туда термином и прикрепляется к товару как видимый атрибут
  (виден во вкладке «Атрибуты», фильтруется). «Таксономия» (`product_brand`) —
  новый способ, по умолчанию. Опция `onecatalog_brand_attribute`.

## [1.1.0] — 2026-06-15

### Добавлено
- **Ручное сопоставление характеристик** OneCatalog → атрибутов WooCommerce: тумблер
  «Manual mapping» на главной странице + отдельная подстраница «Характеристики»
  (фиксированный список характеристик из Wiki API, один выпадающий выбор атрибута на
  строку — дубли привязок исключены). Привязка хранится по стабильному
  `specification_id`. Строгий режим: непривязанные характеристики при импорте
  пропускаются.
- **Статус новых товаров** — настройка (Опубликовано / На утверждении / Черновик /
  Личное). Применяется только к создаваемым товарам; у существующих статус при
  переимпорте не меняется.
- **Хранение бренда (производителя)** — выбор «Тип записи» или «Таксономия» с целевым
  пост-типом/таксономией (по образцу коллекций). По умолчанию — нативная таксономия
  `product_brand`. Класс `BrandImporter`.
- Справочник характеристик из Wiki API (`/specifications/`) с кэшем на язык; новые
  фильтры/экшены: `onecatalog_attr_map_enabled`, `onecatalog_attr_map`,
  `onecatalog_specifications`, `onecatalog_product_status`, `onecatalog_import_brands`,
  `onecatalog_brand_imported`.

### Исправлено
- **Дубли глобальных атрибутов** при разной схеме транслитерации слага (напр.
  «Толщина»: наш `tolschina` против `tolshhina` от плагина Cyr-to-Lat). Существующий
  атрибут теперь ищется по названию (label, регистронезависимо), а не по вычисленному
  слагу — дубликаты больше не создаются.

### Изменено
- Справочник характеристик берётся одним запросом (`limit=1000` + страховочная дочитка
  по `meta.counts`), чтобы не упереться в дефолтный лимит инстанса.
- Полная русская локализация новых строк интерфейса (`.po`/`.mo`/`.pot`).

## [1.0.0]

- Базовый импорт товаров из OneCatalog (Wiki API) в WooCommerce: модальное окно выбора
  товаров, фоновая очередь, зависимости (категории, атрибуты, коллекции, бренды),
  изображения с трекингом качества (max), раздельные артикулы.
